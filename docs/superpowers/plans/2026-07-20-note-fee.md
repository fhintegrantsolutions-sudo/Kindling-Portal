# Note One-Time Fee Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add a per-note one-time fee that is subtracted from the first month's payment (all note types), pro-rated per lender, and shown itemized on the lender + admin schedules and PDFs.

**Architecture:** A nullable `notes.fee` column feeds a new `fee` input on `generateSchedule`, which stamps `fee_amount` onto row 1 only (uniform across interest-only and amortized). The per-lender builder pro-rates it to `my_fee`. Display sites itemize it (gross → less fee → net); the dashboard cashflow and admin ledger net it out of month 1. Recurring `monthly_payment`, projected-income totals, and recorded payments are untouched — the fee only adjusts the projected first payment.

**Tech Stack:** Next.js 16 (App Router, server actions), Supabase Postgres, TypeScript, jsPDF (PDF buttons). No unit-test framework — verify with `npx tsc --noEmit`, `npx eslint src` (baseline: **8 pre-existing problems (6 errors, 2 warnings)** in other files — add none), `npx next build`, and throwaway `npx tsx` scripts for the pure schedule math. Migrations: `scripts/verify/apply-staging-sql.ts <file.sql>` applies to STAGING automatically (it hard-refuses the real DB); the real DB is applied by hand.

Spec: `docs/superpowers/specs/2026-07-20-note-fee-design.md`. Branch: `feat/note-fee`.

```ts

  const rows: MyScheduleRow[] = result.rows.map((row) => {
    const got = receivedByNumber.get(row.payment_number);
    const myPrincipal = got
      ? got.principal
      : Math.round(row.principal_amount * myShare * 100) / 100;
    const myInterest = got
      ? got.interest
      : Math.round(row.interest_amount * myShare * 100) / 100;

      payment_number: row.payment_number,
      due_date: row.due_date,
      my_principal: myPrincipal,
      my_interest: myInterest,
      my_fee: myFee,
      my_balance: runningBalance < 0 ? 0 : runningBalance,
      received_date: got ? got.date : null,
    };
  });
```

## End state

Every note can carry a one-time fee that is subtracted from the first month's payment (interest-only and amortized alike), pro-rated to each lender and shown as an itemized line on their schedule and PDF (and the admin's). Old notes without a fee are visually unchanged. The recurring payment math and all recorded payments are untouched.

## Notes for the implementer
- **Only row 1 ever has a non-zero `fee_amount`.** Every "net the fee" step touches exactly the first-month row/month; don't spread it across the schedule.
- **Don't touch `computeMonthlyPayment`** or `notes.monthly_payment` — the fee is one-time, the recurring payment is not.
- **Received rows are frozen.** `my_fee` is 0 on any row already recorded via `participation_payment_payouts`; the fee only adjusts projected rows.
